# Skills, run inspection, and C# validation

Implementation follows [PLAN.md](../PLAN.md). The native execution protocol is unchanged; run/document metadata and drafts belong to the host.

Automated verification includes `npm run check`, the existing production host/browser smoke and provider SDK browser suites, `npm run test:skills-runs`, and `npm run test:highlighting`. Browser suites use installed Edge. Focused tests cover migration, accepted-request deduplication, operation/tool correlation, interrupted runs, stable cursor search, protected retention, artifact storage, filesystem escapes/collisions, shared preference conflicts, snapshot reads, authoring inventory, trusted source provenance, recoverable interrupted file updates, and revision restoration.

Wide and narrow production UI scenarios exercise skill discovery/selection, disabled enable-and-select, failed submission recovery, offline authoring, recent-run source requests, capsule run navigation, inline message navigation, icon collapse/expansion and keyboard resizing. Long sidebar titles truncate without horizontal overflow. Execution history presents submitted C# and one result with friendly tool names; composer mode/skill selectors and history search/error/tool filters are absent. C# checks exercise exact copying, native selection/undo, composition guards, shortcuts in each editor, scroll synchronization and narrow layout overflow. The production skills/runs fixture applies the host Content-Security-Policy and verifies non-grayscale Shiki tokens for C# and JSON. This reproduces the prior WASM-blocking policy failure and validates the narrowly scoped `wasm-unsafe-eval` correction. Screenshots were inspected during implementation. The initial baseline passed 79 host tests; final test counts and bundle sizes are recorded in the PR.

No live Revit/provider modeling-and-skill-reuse workflow was performed. Native effects and real provider synthesis remain unverified by these mocked tests. The separate expanded browser acceptance matrix deferred in the plan remains deferred.

Adversarial regression coverage injects a partial transaction write, exercises restart with unpublished temporary files and malformed published records, checks library-wide save capacity (including loose C# and oversized files), and verifies edits/restores at capacity. UTF-8 tests cover two-, three-, and four-byte characters at snapshot and authoring page boundaries, invalid offsets, and undersized ranges. These use temporary files and injected failures; they do not simulate a physical power loss.
