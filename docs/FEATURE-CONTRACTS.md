# Skills and run inspection contracts

The installed Pi SDK is 0.85.1. Its resource loader supports `skillsOverride`; tool lifecycle events expose `toolCallId`, `toolName`, `args`, and an end event with `result` and `isError`. Restricted authoring supplies only skill/history tools. Native operations retain their existing transport contract.

History version 2 stores individual run details and summaries outside the live journal. A serialized writer publishes artifacts before references and details before summaries. Interrupted runs are marked on startup; confirmed receipts remain authoritative. Legacy records are archived losslessly without inferred associations. Retention is a separate operation, never part of migration.

Defaults: 500 completed details, 64 MiB aggregate detail text, 2 MiB per detail, 64 KiB per structured tool result, 10 MiB per image, 128 MiB total images, 30 summaries per page (maximum 100), and 512 KiB per console draft. Summary cursors use monotonically increasing run numbers; new arrivals do not shift older pages. Summaries survive detail expiration. Active runs, explicitly selected authoring sources, and unresolved receipts are protected. Admission fails if protected evidence fills a budget. History tools return bounded records with explicit truncation and record references rather than recursive transcripts.

Skills use separate shared user preferences and a cross-process lock, with expected revisions for mutation. Discovery limits are 256 KiB per supported file and 500 supported files per library. Agent context and revision limits are named in the skill module and documented in the skills usage guide. A staged update retains the immediately preceding complete file set before replacing files; interrupted transactions recover under the same lock. External editors do not participate in that lock, so observed conflicts are detected without claiming an atomic guarantee against every external writer.

Drafts use an authenticated per-instance host file, separate from history. Their document reference includes the native instance ID (created once per native service session) and actual document token. Restoration preserves a target only when both still match an open document; otherwise explicit reselection is required. Restoration never dispatches execution.

The per-run detail limit is an admission threshold: a received native result can exceed it and is retained as recovery evidence, while further calls are refused. Individual run transitions serialize only that run, never the entire retained detail history. Legacy records and manual console receipts use separate archives. Protected records that fill aggregate budgets block affected work. Summary output includes a 240-character preview; its persisted search text retains the full request. Artifact cleanup runs on startup, preserves unreferenced files when any missing detail prevents proving that they are orphaned, and never follows user-provided paths.
