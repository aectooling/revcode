# Revcode 0.1.3

## Changes since 0.1.2

- Fix Windows installation failing during `cli.mjs postinstall` with `ExtractToDirectory: Illegal characters in path`. Payload extraction now uses Windows' built-in `tar.exe` instead of PowerShell's .NET ZIP extractor.
- Pass the archive through a file handle and set the extraction working directory directly, supporting Unicode profile paths and long nested dependency paths without command-line path conversion.
- Add an explicit maintainer option to prepare releases without tests or smoke checks. The release receipt records skipped validation; publishing preserves that choice.

## Install or upgrade after publication

Close Revit, then run in PowerShell:

```powershell
npm install -g --allow-scripts=@aectooling/revcode @aectooling/revcode@0.1.3
revcode install
```

For pnpm:

```powershell
pnpm add -g @aectooling/revcode@0.1.3
revcode install
```

The explicit install command handles blocked lifecycle scripts or pending activation. Existing settings and history are preserved. Users whose 0.1.2 installation failed can install 0.1.3 directly.

## Compatibility

Windows x64 with the built-in Windows `tar.exe` and Node.js 22.19 or newer for installation and CLI management. The application bundles Node and self-contained helpers. Revit 2025 uses .NET 8; Revit 2026 requires 2026.5 or newer on .NET 10; Revit 2027 uses .NET 10. Exact supported build ranges are recorded in the release artifact. Binaries are unsigned.

## Release validation

Tests and smoke checks were explicitly skipped for this release preparation at the maintainer's request. Earlier installer-fix validation is not a test of the final 0.1.3 artifact. Packaging still builds the application and records payload and archive integrity hashes.
