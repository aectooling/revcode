# MVP integration contract

## Atomic batch extension

Browser `POST /api/execute` and `revit_execute_csharp` accept a discriminated request:

```typescript
{ mode: "batch", documentToken: string, transactionName?: string,
  steps: { name: string, code: string, usings?: string[] }[],
  verify?: { code: string, usings?: string[] } }
```

Browser requests additionally require `requestId`. Top-level `code`/`usings` are rejected for batches; steps/verification are rejected for single-snippet modes. Require 1–20 steps, names of 1–100 characters, and at most 64 KiB UTF-8 combined code/imports including verification. The complete normalized batch is journaled as one operation, then forwarded unchanged with native `kind: "execute"` and `operationId`. Deduplication fingerprints include every step and verification; no per-step replay is supported.

Native validates the target again, compiles all snippets before scheduling one callback, and attaches zero-based `stepIndex` and `stepName` to diagnostics (`verification` uses index `steps.length`). Compilation failure reports `NotStarted`. Internal compiler modes `batch` and `verify` add contract restrictions to existing synchronous execution checks.

The terminal `result` is `{steps: [{name, status, result?, error?}], verificationStatus: null | "notRun" | "running" | "passed" | "failed"}`. Step status is `committed` only after confirmed assimilation, `rolledBack` after confirmed group rollback, `notRun` if execution never reached it, or `unknown` if cleanup was unconfirmed. On rollback/unknown, per-step result values are removed. Compilation/target failures may have no result envelope; compilation diagnostics identify the failing snippet. Overall `transactionStatus` describes the group. A passed verification is an observation before group finalization, not independent evidence of commitment.

Aggregate results are checked before assimilation; 240 KiB is reserved for materialized step values within the 256 KiB final result budget. Logs are bounded to 100 lines and 16,000 characters across all steps and verification. An unknown native group outcome fences the process; disconnect recovery uses the existing retained operation receipt.

## Existing transport and single-snippet contract

One hidden Node host per Revit process; browser loopback HTTP and mandatory native ZeroMQ bridge, with separate browser and native tokens. All JSON uses camelCase. Browser is React/Vite, built to `dist/web`; host TypeScript compiled to `dist/host/index.js`. Package root contains `runtime.json`: `{ "nodePath": "runtime/node.exe", "hostPath": "dist/host/index.js", "compilerPath": "compiler/Revcode.Compiler.exe" }` (paths relative to package root). Add-in lives in `addin/<year>/Revcode.Revit.dll`; find runtime.json by walking up from assembly directory.

Native launches Node hidden with arguments `hostPath --instance <uuid> --parent-pid <pid> --discovery <absolute-json-path> --data-dir <absolute-instance-data-dir> --user-dir <absolute-private-user-dir>`. Native token is passed in child environment `REVCODE_NATIVE_TOKEN`, never logged. Node atomically writes discovery `{ protocolVersion: 1, instanceId, url, browserToken, nativeEndpoint }`, user-only ACL inherited from private data directory. Native opens `url/#browserToken`. Browser removes fragment and remembers token in sessionStorage, attaches `Authorization: Bearer TOKEN` to API fetch requests. No query-string tokens. Host validates Host and Origin; accepts only loopback local clients. Native sets Windows user-only ACLs on both instance and shared user directories. Shared user directory retains model definitions and selection across launches; credentials use the shared Pi auth file (or REVCODE_PI_AUTH_PATH), and the instance directory retains its transcript/journal.

Native wire: Node `zeromq.Router` binds `tcp://127.0.0.1:*`, C# `NetMQ.DealerSocket` connects to discovery nativeEndpoint. Dealer sends one UTF-8 JSON frame; Router receives route identity then JSON frame. Responses reverse that framing, with no empty delimiter. Every native message includes `{type, token, payload?}`; tokens compared securely. A valid context establishes the authenticated route. Native uses one socket-owner transport thread and concurrent outbound queue. Heartbeats resend latest immutable context every two seconds even while Revit is busy. Context and operation messages are sent over this same connection; no HTTP native endpoints.

- `type: "context"`, payload: `{ instanceId, revitVersion, revitBuild, runtime, document: null | { token, title, isFamily, isReadOnly, activeView: string, selection: string[] } }`. The payload also includes `documents`, an array of document snapshots for every open non-linked document. Inactive snapshots have empty activeView/selection. Tokens are stable for an open document lifetime. Read Revit objects only in API context.
- Host to native: `{type: "command", command: { kind: "execute", operationId, documentToken, code, usings?: string[], mode: "query" | "modify" | "api", transactionName?: string }}` or command `{ kind: "cancel", operationId }`. Socket polling continues during compilation/execution to receive cancellation.
- `type: "operation"`, payload: `{ operationId, status: "compiling" | "queued" | "running" | "succeeded" | "failed" | "cancelled" | "unknown", result?: unknown, logs?: string[], diagnostics?: { severity: string, message: string, line?: number, column?: number }[], error?: string, transactionStatus?: string, elapsedMs?: number }`. Terminal outcomes retained natively and repostable; duplicate operation IDs never execute twice. Unknown fences further execution.
- `type: "disconnect"`: shutdown notification (best effort).
- Host to native: `{type: "ack", operationId, status}` acknowledges a persisted native receipt. Native periodically resends its latest unacknowledged receipt, including terminal results, and keeps the operation identity for duplicate suppression for the Revit process lifetime.

Browser endpoints (all `/api/*` authenticated):

- `GET /api/state`: `{ instanceId, context: <native snapshot|null>, connected: boolean, busy: boolean, messages: { id: string, role: "user"|"assistant"|"system", text: string }[], operations: <operation records>[], settings: { provider: string, model: string, configured: boolean }, providers: <Pi provider summaries>[], auth: <transient auth state> }`. Never returns API keys or access/refresh tokens. Provider summaries include id, display name, models, authenticated state, available OAuth/API-key methods, credential source label, and whether logout is available. Auth state exposes only the active sign-in URL/device code, prompt fields/options, busy/completed/error status; it is not journaled.
- `POST /api/settings`: `{provider, model, apiKey?: string}`. Blank/omitted key preserves stored key. Host owns secrets and Pi auth. Return sanitized settings. The complete installed Pi provider catalog and supported auth methods are exposed through the provider setup flow.
- `POST /api/auth/login`: `{provider, authType: "oauth" | "api_key", apiKey?: string}` starts Pi's provider-specific interaction. Returns 202; UI follows transient `auth` in state/events. Sign-in has a five-minute cancellation deadline.
- `POST /api/auth/respond`: `{requestId, value}` answers the current secret/text/manual-code/select prompt; stale IDs are rejected. Values are never added to chat history.
- `POST /api/auth/cancel`, `/api/auth/refresh`: `{}` cancels an in-progress sign-in or reloads provider/credential metadata.
- `POST /api/auth/logout`: `{provider}` removes a stored credential through Pi. The default credential store is shared with Pi, so logout affects other Pi clients.
- `POST /api/auth/provider`: `{id, name?, baseUrl, apiKey?, models: {id,name?}[]}` registers a custom OpenAI-compatible provider. Definitions are stored under a cross-process lock in shared user-dir/models.json, credentials through Pi. HTTP(S) endpoints are supported, including keyless local endpoints; embedded URL credentials are rejected.
- `POST /api/chat`: `{ requestId: uuid, text: string }` returns 202 `{requestId}`; duplicate request IDs do not prompt twice. Host streams Pi events into persistent messages, exposes `revit_execute_csharp` and `revit_capture_view`. Require Revit connected and provider configured.
- `POST /api/execute`: `{requestId: uuid, code, usings?, mode, documentToken?: string | null, transactionName?}` returns 202 `{ operationId }`; direct C# console for testing without model credentials. Same native executor as Pi. Bind the supplied open-document token, or the active document token at submission when omitted. Explicit null selects no document (query/api only). Never fall back from an invalid token. Reject while another turn or operation owns execution.
- `POST /api/cancel`: stop generation and cancel outstanding operation; no force-kill of Revit.
- `GET /api/events`: SSE via authenticated fetch streaming (not EventSource). Events `state` contain full sanitized state (debounce streaming updates), `error` contains `{message}`. Initial state sent on connect. UI can fall back to polling `/api/state` every 1s for MVP simplicity; no replay of POSTs on reconnect.

Operation records extend native updates with `operationId`, `code`, `mode`, `documentToken`, `createdAt`. Limit source to 64 KiB, result/log payloads, and retained UI state. Journal source/intent before native dispatch. Native disconnection during possibly-started operation is unknown; never replay mutations. Native operation update can reconcile an unknown host record. Host restart must not replay old chat/tool calls. Multiple Revit instances have independent tabs/hosts in MVP.

Script body ABI: `object? Execute(RevcodeContext ctx)`, default usings System, System.Linq, System.Collections.Generic, Autodesk.Revit.DB, Autodesk.Revit.UI. Context members `Doc` (bound target), `Documents`, `GetDocument(token)`, `GetDocumentToken(document)`, `UiDoc` (active UI document), `UiApp`, `Log(string)`, `CheckCancellation()`. Host owns the target transaction in modify mode. API mode opens no transaction and reports ApiManaged on success; exceptions after invocation starts report unknown because earlier side effects cannot be rolled back. Script returns JSON-safe materialized values. Default query example: `return new FilteredElementCollector(ctx.Doc).OfClass(typeof(Level)).Cast<Level>().Select(x => new { id = x.UniqueId, name = x.Name }).ToArray();`.

Compiler worker: isolated executable accepts JSON on stdin `{code, usings?, references: string[], mode?: "query" | "modify" | "api"}`; references include the contract assembly path. Returns `{assembly?: base64, pdb?: base64, diagnostics: {severity,message,line?,column?}[]}` on stdout. No Revit API execution in worker. Publish self-contained .NET 10 win-x64 compiler, independent of the Revit host's runtime; do not ship Revit API DLL copies. Add-in targets net8.0-windows for 2025/2026, net10.0-windows for 2027 via RevitYear MSBuild property and installed Revit references. NetMQ 4.0.2.2 is used for the .NET 8 add-ins and 4.0.4.3 for .NET 10; the .NET 8 transport must not bring Immutable 10 into Revit's load context.

The capture tool submits a fixed API-mode C# image export through the existing execute path. Native results contain view metadata or `captureError`; the host reads the PNG from its unique instance capture directory and returns Pi image content without placing image bytes in the operation journal. No new wire command is required.
